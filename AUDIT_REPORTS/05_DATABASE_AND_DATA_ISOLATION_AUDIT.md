# 05 — Database and Data Isolation (static; NOT TESTED against a live DB)
**Schema** (`database/migrations/*`): `users` (unique email, `role` string), `workspaces` (PK/FK `user_id`, `revision`, jsonb `data`), `licenses` (unique `key_digest`, unique nullable `claimed_by` FK, `installation`), `audit_events`, `sbcc_profiles`, `sbcc_images` (composite PK `user_id,slot`), unused `password_reset_tokens`.
**Isolation:** every data endpoint reads/writes by `$r->user()->id`; no client-supplied owner id. `productImage` also checks the product id exists in the caller's own workspace. No cross-tenant path found by reading. Runtime two-account test: NOT TESTED (existing `WorkspaceIsolationTest` has 2 methods).
**Concurrency:** workspace save uses compare-and-swap on `revision` (good). Licence redeem/activate use row locks. Workspace first-creation race fixed on branch (A-13).
**Issues:** blob model with caps (A-03); no CHECK constraint on `role`/`status` values (add enums/checks); money as JSON floats (A-12); `audit_events` has no retention (per-save rows removed); `sbcc_images` stores base64 in a text column with no quota; down-migrations drop tables (never run on production); no backup/restore procedure — use `pg_dump` nightly plus a tested restore (blocker for launch).
